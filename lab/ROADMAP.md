# ROADMAP — OrthoLoC по блоках

Принцип: кожен блок = **один результат, який можна запустити й показати** (скрипт / графік / рядок у таблиці метрик).
Блоки 0–5 — ядро (мінімум для співбесіди і README). 6–8 — якщо є час. Таймбокс вказано орієнтовно.

Легенда: 🖥 Mac (CPU) · ☁️ Colab (GPU) · 🧰 що йде в `lab/tools/` · 🎤 теми співбесіди

---

## Блок 0 — Середовище і санітарний запуск (½ дня) 🖥
- **Зробити:** venv, `pip install -e .`, запуск `run-localization ... --matcher GT --device cpu` на обох демо-семплах.
- **Готово, коли:** є вивід пози + K, і TE/RE для GT-матчера ≈ 0 (це перевірка геометрії, а не матчингу).
- **Покрутити:** `--pnp_mode cv2|poselib|pycolmap` — чи однаковий результат?
- 🎤 Навіщо «оракульний» бейзлайн (GT matches) в експерименті? Що він ізолює?

## Блок 1 — Дані та системи координат (1 день) 🖥
- **Зробити:** власний скрипт, який відкриває `.npz`, показує query / DOP / DSM, і **вручну**:
  піксель DOP + DSM + `scale` → 3D-точка → проєкція в query через `K·[R|t]` (GT). Накласти точки на query.
- **Готово, коли:** спроєктовані точки лягають на ті самі об'єкти (дахи, розмітка) у query; похибка видима очима < кількох px.
- 🧰 `lab/tools/raster_geo.py` (pixel↔world для ортографічного растра), `lab/tools/camera.py` (project / backproject / camera center).
- 🎤 Перспективна vs ортографічна проєкція; DOP / DSM / DTM; GSD; world→cam vs cam→world; WGS84 / UTM / ECEF / ENU.

## Блок 2 — Матчинг (1 день) 🖥 + ☁️
- **Зробити:** `run-matching` з легким матчером на Mac (напр. XFeat / SuperPoint+LightGlue), важким — у Colab (GIM+DKM або RoMa).
- **Готово, коли:** таблиця: матчер × (к-сть матчів, ME медіанна похибка матчингу px, час).
- **Покрутити:** `--angles` (поворот query), `--min_conf`, `--scale_query_image`.
- 🧰 `lab/tools/viz_matches.py` — візуалізація відповідностей з кольором за похибкою.
- 🎤 Sparse vs semi-dense vs dense матчери; чому LoFTR-подібні слабкі на aerial→ortho; domain gap.

## Блок 3 — Lifting + PnP RANSAC (1 день) 🖥
- **Зробити:** власна реалізація: матчі → lift через DSM → фільтри (conf, NaN висоти) → `cv2.solvePnPRansac` (EPnP) → TE/RE.
  Порівняти з `ortholoc.utils.pose.run_pnp`.
- **Готово, коли:** твоя реалізація дає ті самі TE/RE (± невелика різниця) на демо-семплах.
- **Покрутити:** `--reprojection_error` (поріг RANSAC), `--num_points`, к-сть ітерацій.
- 🧰 `lab/tools/pnp.py`, `lab/tools/metrics.py` (TE, RE, recall@thresholds).
- 🎤 PnP: мінімальна к-сть точок, P3P vs EPnP, RANSAC (к-сть ітерацій від inlier ratio), чому reprojection error, а не 3D-похибка.

## Блок 4 — Калібрування LM (1 день) 🖥
- **Зробити:** `--no_intrinsics`; розібрати `run_calibration`. Експеримент: зсунути початковий focal на ±20 % і подивитись на TE vs RFE.
- **Готово, коли:** графік, що показує неоднозначність focal ↔ translation (висота камери «компенсує» фокус).
- 🎤 Levenberg–Marquardt vs Gauss–Newton; bundle adjustment; спостережуваність (observability) параметрів; чому фіксують principal point.

## Блок 5 — AdHoP (1 день) 🖥 / ☁️
- **Зробити:** розібрати `adhop_refinement`; повторити ідею: гомографія → warp DOP → повторний матчинг → назад через $H^{-1}$ → PnP.
- **Готово, коли:** таблиця з/без `--use_adhop` для ≥2 матчерів (TE, RE, ME, час).
- 🎤 Гомографія і коли вона валідна (площина / чисте обертання); DLT + нормалізація Хартлі.
